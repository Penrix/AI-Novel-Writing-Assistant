# 音乐缩谱正文生产接入｜独立试验分支

状态：**开发中，尚未接入实际章节生产，禁止当成可用的音乐缩谱模式。**

## 当前采用的低成本分工

- **保留原软件**：拆书、创作承接合同、自动导演剧情规划、人物世界资料、章节任务、小说管理。
- **只替换正文制作方法**：在剧情与章节任务已经确定后，使用作者提供的成功原著 A 实际正文，按音乐缩谱 07—17 制作 B 正文。
- **不做**：武戏技能开发、二级/三级蒸馏、重新设计剧情导演、改动 OAuth。
- 07 的“B连续作曲”在本接入中受已确定的章节剧情约束；不把软件剧情规划偷换成它自己的整书编剧权。
- **v0.4 的真实独立提示词必须导入**，不能拿此说明、v0.2 草案或通用正文 writer prompt 冒充 v0.4。

## 现有工作流与改造点

原软件：

~~~
拆书 -> 剧情规划 -> 章节任务/场景卡
                        -> novel.chapter.writer 整章写作
                        -> 开篇多样性/相似度改写/自动补字
                        -> 质量检查/修文 -> 章节保存/时间线与事实更新
~~~

计划增加的**可选**音乐正文：

~~~
拆书 -> 剧情规划 -> 章节任务/场景卡（保持原样）
                        +
                  A 原著正文位置与版本
                        +
                  B 已有正文及人物状态
                        ↓
                 07 → 08 → 09 → 08
                        ↓
                    10 → 11 → 12
                        ↓
                    13 → 14 → 15 → 16
                        ↓
                     作者验收
                        ↓
                  17 写回提案
                        ↓
           软件既有生命周期中的受控提交
~~~

08 前后两次职责不同；10可按人物多次执行；12可按当前小节多次执行，不要把“11份提示词”误当成“只能调用11次模型”。
碰见阶段责任不匹配，返回指定的上游工序。绝不靠下游自由补写来遮盖上游失误。

**禁止自动改写音乐正文。** 原 chapterWritingGraph.ts 中的 continuityNode（开头多样性、相似度改写）、enforceTargetLength（自动续写）不能默认作用于音乐成品。后续通用质量检查原则上可产出只读报告，但不得自动用通用风格规则覆盖音乐成品。角色事实/时间线同步可以复用，但应在正式采纳正文后触发。

## 第一批实际代码

- musicScoreContract.ts：纯状态机；真实A定位、章节基准版本、阶段顺序、READY/RETURN/BLOCKED/NEEDS_AUTHOR、阶段产物引用、作者认可、17 写回提案。**无模型调用、无数据库写入。**
- musicScorePromptBundle.ts：从作者实际提供的11份独立v0.4提示词导入，检查版本、唯一文件与 SHA-256。缺失即停止，绝不静默退回普通写作或早期草案。
- server/tests/musicScoreContract.test.js：阶段顺序、两次08、回退、暂停、章节版本和作者验收。
- server/tests/musicScorePromptBundle.test.js：11份提示词导入与缺失、旧版本拒绝。

此处的 artifactRef 是**将来持久化产物的引用契约**，当前没有实现数据库/磁盘产物保存；因此不能声称已经具备断点恢复或全部审美生产。

## 下一轮开发的真实断点

1. 导入准确的 v0.4 原文件，并保存只读版本与校验值；保留原始长文作为形成史和争议时的回读来源。
2. 添加按阶段存储产物的持久化服务（章节级隔离、修订号、作者确认；可按需加载、不重复上传全书）。
3. 通过软件现有统一模型路由逐工序调用提示词；每一工序保存完整结果与引用，支持主动返回指定上游步骤。
4. 增加一个**独立、可选**的正文制作入口；旧版 writer 完全不变，不得因为模型不可用而静默转入普通自由写作。
5. 作者采纳16阶段正文后，以实时章节版本校验执行17的受控写回，接入既有章节生命周期与人物事实同步；A指针不能在正文实际采纳前推进。
6. 只在质量检查产生具体错误时回到相应责任工序；通用审核不拥有音乐成品的审美改写权限。
7. 最后再验证类型、自动测试、Windows 桌面与真实 A→B 正文效果。机械通过不等于审美验收。
